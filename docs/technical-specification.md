# Техническое задание на AIESEC Match

Версия 1.0 от 27 ноября 2026 года. Базовая ревизия проекта — `7ea8265`.

## 1. Назначение и границы системы

AIESEC Match помогает кандидату найти подходящие возможности AIESEC по анкете, понять причины рекомендаций и сохранить интересные предложения. Платформа поддерживает три программы — Global Talent, Global Teacher и Global Volunteer. Актуальность возможностей определяется по данным каталога AIESEC. Подача заявки происходит во внешней системе AIESEC. Сигнал `applied` в AIESEC Match отражает действие пользователя внутри платформы.

| Роль | Доступные действия |
| --- | --- |
| Гость | Регистрация, вход и просмотр публичной карточки возможности |
| Кандидат | Анкета, персональный подбор, избранное, история, статистика, уведомления и настройки аккаунта |
| Оператор каталога | Диагностика источника, запуск синхронизации, проверка результатов через служебный API парсера |
| Внешний Telegram-сервис | Подтверждение привязки аккаунта, получение и подтверждение обработки уведомлений через внутренний API |

## 2. Функциональные требования

### Аккаунт и согласия

| ID | Требование |
| --- | --- |
| AUTH-01 | Пользователь может зарегистрироваться и войти по email и паролю. После успешной авторизации API возвращает JWT. Защищённые операции выполняются от имени владельца токена. |
| AUTH-02 | При настроенной Telegram-интеграции веб-клиент принимает `initData` Telegram WebApp. Backend проверяет подпись и срок действия данных. Для привязки к существующему аккаунту сервис выдаёт одноразовый код, который обрабатывает внешний Telegram-сервис. |
| AUTH-03 | Пользователь может сменить пароль после проверки текущего. При удалении аккаунта система помечает учётную запись удалённой и прекращает доступ по ранее выданному токену. Смена email в режиме разработки описана в разделе 5. |
| CONS-01 | Для сохранения анкеты и запуска подбора требуется согласие на обработку персональных данных актуальной версии. При обновлении версии веб-клиент предлагает принять новый текст. Маркетинговое согласие оформляется отдельно и может быть отозвано. API отклоняет отзыв обязательного согласия. |

[Контракт аккаунта](../backend/app/api/auth.py), [правила согласий](../backend/app/application/consent_service.py), [тексты согласий](../backend/app/forms/consents.v1.yaml).

### Анкета

| ID | Требование |
| --- | --- |
| PROF-01 | Пользователь заполняет пошаговую анкету. Состав полей, их условная видимость и справочники определяются серверной схемой. Анкета охватывает программы, персональные данные, языки, учёбу, опыт, интересы, географию, сроки, бюджет и мотивацию. |
| PROF-02 | При указании даты рождения допустимый возраст составляет от 18 до 31 года включительно. Для запуска подбора требуются дата рождения, уровень английского, статус учёбы и хотя бы одно значение среди программ, профессиональных сфер и активностей. |
| PROF-03 | Каждое успешное сохранение создаёт новую версию анкеты и обновляет показатель заполненности. Пользователь может просматривать список версий и снимок выбранной версии. Если переданный `If-Match` устарел, API возвращает конфликт и сохраняет актуальные данные. |

[Схема анкеты](../backend/app/forms/form_schema.v2.yaml), [проверка заполненности](../backend/app/domain/completeness.py), [сервис профиля](../backend/app/application/profile_service.py).

### Каталог

| ID | Требование |
| --- | --- |
| CAT-01 | Парсер загружает возможности из AIESEC GraphQL, нормализует записи и ограничивает импорт настроенной географией. Повторная загрузка одного ID обновляет существующую запись. Целевые страны и локальные офисы задаются конфигурацией. |
| CAT-02 | Парсер поддерживает полную загрузку, инкрементальное добавление и сверку открытых возможностей. Сверка обновляет данные о местах, закрывает исчезнувшие возможности и может переоткрыть вернувшиеся. Просроченные записи закрываются локально. Ошибка или подозрительно неполная выдача источника должна предотвращать массовое закрытие. |
| CAT-03 | Оператор может запустить синхронизацию вручную, посмотреть историю и статистику запусков и запросить обновление отдельной возможности. Для служебных операций требуется ключ парсера. Одновременно выполняется один процесс синхронизации. |
| CAT-04 | Публичный API предоставляет список и карточку возможностей. Список поддерживает текстовый поиск, фильтры по программе, стране, локальному офису, семейству и статусу, сортировку и пагинацию. По умолчанию выдаются открытые возможности. Веб-интерфейс открывает карточки из рекомендаций и других экранов. Маршрут `/opportunities` перенаправляет на результаты. |

### Подбор рекомендаций

| ID | Требование |
| --- | --- |
| MATCH-01 | Сервис выбирает программы в порядке приоритета: явные фильтры запроса, программы анкеты, вывод по профессиональным сферам и активностям. Преподавательские сферы указывают на Teacher, остальные профессиональные сферы на Talent, активности на Volunteer. |
| MATCH-02 | Из подбора исключаются закрытые и просроченные возможности, варианты без мест, записи с несовместимыми обязательными языками и известными ограничениями по гражданству или образованию. Учитываются страна из фильтра, исключённые ID, скрытые и отклонённые предложения. Платные варианты исключаются при отказе кандидата платить. Лимит бюджета в евро применяется к ценам в EUR и ценам без кода валюты. |
| MATCH-03 | Стратегия `weighted_v1` рассчитывает оценку по взвешенным признакам. Веса зависят от программы и включают профиль, навыки, языки, географию, длительность, стоимость, оценку шансов и свежесть записи. В каждой программе система оставляет лучший вариант на семейство и показывает ранг, оценку, метку и причины. Лимит публичного API — от 1 до 30 на программу, по умолчанию 10. |
| MATCH-04 | Backend сохраняет запуск с версией профиля, фильтрами и результатами. Повторный запрос того же пользователя с тем же `Idempotency-Key` возвращает ранее сохранённый запуск. Пользователь может открыть последний успешный или конкретный собственный запуск. При чтении результатов закрытые карточки исключаются по актуальному состоянию каталога. |

### Обратная связь, история и уведомления

| ID | Требование |
| --- | --- |
| ACT-01 | API сохраняет сигналы `opened`, `liked`, `disliked`, `hidden` и `applied`, при необходимости связывая их с запуском. Пользователь может убрать сигнал и открыть список избранного. API предоставляет отдельный список скрытых возможностей. |
| ACT-02 | История объединяет запуски подбора и обратную связь, поддерживает фильтры по типу и датам и постраничную выдачу. Личная статистика показывает заполненность анкеты, распределение по программам и интересам, статистику рекомендаций и активность. Для ряда активности поддерживаются периоды 7, 30, 90 дней и весь срок. |
| NOTIF-01 | Пользователь может сохранять настройки уведомлений о новых совпадениях, порог оценки от 0 до 1 и канал Telegram. Веб-клиент показывает сохранённые уведомления, которые можно пометить прочитанными. Внутренний API поддерживает резервирование уведомлений для обработки и подтверждение результата внешним потребителем. |

## 3. Архитектура, данные и эксплуатация

| Компонент | Ответственность |
| --- | --- |
| Web | React и TypeScript. Пользовательские экраны и вызовы Backend API. |
| Backend | FastAPI, публичный REST под `/api/v1`, внутренний API под `/internal/v1`, правила доступа, профили, история, оркестрация подбора. |
| Parser | FastAPI, OAuth и GraphQL-клиент AIESEC, ручная и плановая синхронизация, нормализация возможностей. |
| Matcher | FastAPI, расчёт подбора по `POST /v1/match`, чтение открытых возможностей, фильтрация и ранжирование. |
| PostgreSQL | Схема `core` для аккаунтов и действий, `parser` для возможностей и синхронизации, представления `catalog` для чтения Backend и Matcher. |
| Развёртывание | Docker Compose, Nginx для веб-клиента, миграции Alembic и проверки состояния сервисов. |

Парсер пишет в таблицы схемы `parser`. Backend и Matcher читают каталог через SQL-представления `catalog.opportunity_v1`, `catalog.opportunity_requirement_v1` и `catalog.sync_state_v1`. Backend передаёт Matcher псевдоним профиля на базе HMAC и ограниченный набор полей анкеты. Дата рождения и текст мотивации остаются в Backend. Пароли хранятся как bcrypt-хеши, параметры доступа задаются через окружение.

## 4. Критерии приёмки

| Сценарий | Ожидаемый результат |
| --- | --- |
| Регистрация, вход и удаление | После входа доступен собственный аккаунт. После удаления сохранённый токен теряет доступ к защищённым операциям. |
| Сохранение анкеты | Без актуального согласия сохранение отклоняется. После принятия согласия валидная анкета создаёт версию. Сохранение с устаревшим `If-Match` не перезаписывает анкету. |
| Подбор на тестовом каталоге | При полной для подбора анкете возвращаются подходящие возможности с оценкой и причинами. Закрытые записи и записи без мест исключаются. Повтор с тем же ключом возвращает тот же ID запуска. |
| Избранное и скрытие | Понравившаяся возможность появляется в избранном и исчезает после удаления сигнала. Скрытая возможность исключается из следующего подбора. |
| История и статистика | Запуск и сигналы появляются в истории пользователя, а статистика отражает соответствующие события. Чужой запуск недоступен по его ID. |
| Синхронизация и каталог | После успешного импорта возможность видна через публичный API. Повторный импорт сохраняет одну запись на ID. Сбой источника не вызывает массового закрытия записей. |
| Настройки и уведомления | Изменённые настройки доступны после повторного чтения. Подготовленная тестовая запись появляется у владельца и меняет состояние после отметки о прочтении. |
| Ошибочные и пустые состояния | Веб-клиент отображает отсутствие результатов и ошибки API, а при потере сети открывает страницу офлайн. |

Приёмка полного стека проводится командами `make test` и `make test-system` на изолированных данных. Контракт с внешним AIESEC проверяется отдельно через `make test-live` с действующим токеном. Для нагрузки предусмотрен сценарий k6. Целевые значения нагрузки, задержки и доступности для рабочего окружения требуют согласования.

[Сквозные сценарии](../qa/test_e2e_user_flow.py), [команды тестирования](../Makefile), [нагрузочные сценарии](../loadtest/).

## 5. Оговорки текущей реализации

| Область | Состояние на базовой ревизии |
| --- | --- |
| Уведомления о совпадениях | Модуль формирования outbox реализован отдельно. В потоке создания рекомендаций вызов модуля отсутствует. Доставка через Telegram зависит от внешнего потребителя, которого нет в репозитории. |
| Смена email и восстановление пароля | В dev-режиме API выдаёт код смены email в ответе. В обычном режиме запрос требует почтового провайдера и завершается ошибкой. Публичный сценарий восстановления пароля отсутствует. |
| Асинхронный подбор | Режим `async` возвращает HTTP 202 после выполнения того же синхронного вызова Matcher. Фоновая очередь для этого режима отсутствует. |
| Счётчик просмотров | Аналитика считает события `viewed`, а API обратной связи принимает `opened`. Сквозной подсчёт просмотров через публичный API требует согласования этих значений. |
